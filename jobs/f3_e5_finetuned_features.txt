# E5 -- does a fine-tuned representation still encode the acquisition era?
#
# The paper's era column is one frozen-probe decode per backbone; the exploitation claim is
# about fine-tuned arms. No checkpoints or activations were ever stored, so answering this
# needs the fine-tuned arms rerun with the representation dumped.
#
# `scripts/04_train_single_view.py --save-features` (new) writes, per fold, the
# penultimate-layer vector of every patient in that fold's train/val/test partitions, under
# <output-dir>/features/r{repeat}_f{fold}.npz. It is a forward pass in eval mode after
# training, so it cannot alter what the run learns; the predictions of these runs must come
# out identical to the ones already in results/, and that is the first thing to check.
#
# The hyperparameters below are copied from the config.json of the existing runs
# (30 epochs, batch 16, lr 1e-4, backbone lr scale 0.01, 3 warmup epochs, no early stopping,
# seed 42) precisely so that they reproduce. Output goes to *new* directories: the existing
# results are what the submitted paper reports and must not be overwritten by a rerun that
# happens to differ.
#
# Cost: two arms x 25 folds x 30 epochs over 231 frontal images. This is the same work the
# original runs did, plus one forward pass per fold. Storage is about 20 MB per arm
# (231 patients x 25 folds x 768 float32, compressed).
#
# ---------------------------------------------------------------------------------------
# Step 0 -- smoke test, one fold, before spending the full budget. Check that
# features/r1_f1.npz appears and that its train/val/test arrays have the expected shapes.
# --limit-folds writes no results by design, so this costs one fold and proves the plumbing.
